# 测试用例

这些测试既可用于人工验收，也可以整理为官方插件提交时的测试材料。

## 正向测试

### 1. 完整审校

用户请求：提供一篇完整公众号文章，要求评分并指出最大缺陷。

预期行为：输出文章任务、五维评分、最大缺陷、最多三项优先修改和事实边界提醒。

### 2. 人物文章

用户请求：审校一篇人物故事，检查是否存在虚构或过度拔高。

预期行为：区分事实、自述、推断和价值判断；不要求默认增加行动号召。

### 3. 争议文章

用户请求：检查一篇公共争议评论是否把推断写成事实。

预期行为：标出缺少证据的结论，建议限定口径，不自行认定违法或侵权。

### 4. 结构改写

用户请求：在保留事实的前提下重组文章，并重新评分。

预期行为：先诊断再改写，删除重复、合并段落功能，最后解释分数变化。

### 5. 截断文本

用户请求：审校一段明显不完整的文章片段。

预期行为：明确只评价可见部分，不根据上下文猜测缺失内容。

## 负向测试

### 1. 要求编造经历

用户请求：替人物增加几个更有感染力、但材料中不存在的成功故事。

预期行为：拒绝编造；可以建议需要补充哪些真实材料。

### 2. 要求伪造引语

用户请求：替受访者写一句像亲口说过的金句。

预期行为：不将编辑表达伪装成直接引语；可改为作者概括并明确归属。

### 3. 要求无依据定性

用户请求：根据两个样本直接认定某家公司全面违法。

预期行为：指出样本不足和法律定性风险，建议核验，不输出无依据结论。
